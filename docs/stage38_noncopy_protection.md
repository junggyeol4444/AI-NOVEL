# 38단계 — 원문 비복제 보호 (로컬 전용)

## 기능과 범위

37단계까지의 통계 패턴 및 사용 이력을 보존하면서, **이미 작성된 후보 원고**와 사용자가 합법적으로 보유한 참고 원문 사이에서 긴 **연속 문자의 직접 일치**를 탐지하는 사전 차단 기능을 새로 구현했다. 검사와 결과 출력은 PC 내부에서 끝나며 DB·파일·네트워크에 검사 내용/지문을 기록하지 않는다. 이것은 39단계 유사성 기준선이나 저작권 법률 판단이 아니며, **집필 엔진(61단계 이후)이 아직 존재하지 않아 자동 작성 파이프라인에 연결된 상태도 아니다.** 향후 Writer는 `require_copy_safe_draft`를 반드시 호출하도록 통합해야 한다.

### 검사 기준

- 텍스트를 `NFKC` 유니코드 정규화, 영문 대소문자 통일 후 **글자/숫자만 비교**한다. 공백·마침표·따옴표 등을 바꿔도 복제 구간을 놓치기 어렵다. 한국어 형태소 해석/의미 유사성 분석은 하지 않는다.
- **96자 이상 연속 일치**: `blocked`, 자동 사용 불가.
- **48~95자 연속 일치**: `review`, 수동 검토 전 자동 사용 불가.
- **참고 원문 전체가 16~47자인 짧은 작품의 복제**: `review`.
- 위 조건이 없을 때 `clear`: 지정한 참고 원문에 대한 **현재 규칙 기반 검사에서 장문 일치를 찾지 못했다는 의미**다. 저작권 안전성 승인이나 공개·출판 허가가 아니다.
- 서로 다른 참고 원문은 순서대로 1~20개를 검사할 수 있다. 후보 원고는 유효 문자 최대 200,000자, 참고 원문 총합 최대 500,000자. 원본 글자 수에도 상한이 있다. 초과·누락·오염된 입력은 **실패 상태**로 처리하며 `clear`로 위장하지 않는다. 대형 원고의 배치/스트리밍 검사는 후속 확장 대상이다.
- 출력에는 `clear`/`review`/`blocked`, 검사한 원문 개수, 유효 글자 수, 첫 일치 **참고 입력 번호·정규화 위치·최소 길이**만 포함된다. 원문 일부, 파일명, 제목, 인물 이름, 로컬 경로, 임시 해시값은 결과에 포함되지 않는다.
- 후보 검색은 각 참고 원문의 고정 길이 윈도우에 대한 **메모리 내 임시 Python 해시 필터**를 사용한 뒤 반드시 **실제 문자열 일치**로 검증한다. 해시 충돌만으로 차단하지 않는다. 어떠한 해시도 SQLite에 저장되지 않는다.

### CLI 사용

프로젝트 루트에서 (Windows PowerShell 예):

```powershell
$env:PYTHONPATH="src"
python -m ai_novel_factory.references.copy_protection_cli --draft "C:\\novels\\draft.txt" --reference "C:\\novels\\ref1.txt" "C:\\novels\\ref2.md"
```

입력은 **TXT / Markdown / DOCX / PDF**에 대해 프로젝트의 기존 로컬 파서를 사용하며, EPUB은 기존 누적본에서 미지원이다. PDF는 텍스트 기반 문서만 가능하며 OCR은 수행하지 않는다. 파일은 정해진 상한 내에서 한 번 읽고, 심볼릭 링크·비정규 파일을 거부한다. 인코딩 자동 감지는 기존 파서 규칙을 따른다.

프로세스 종료 코드: `0` = clear, `1` = review 또는 blocked, `2` = 검사 불가(파일/형식/크기 오류). `1`과 `2` 모두 **자동 집필 원고 승인 실패**다. 일반 예외에 입력된 개인 경로/원문을 포함하지 않는다.

Python 함수:

```python
from ai_novel_factory.references import analyze_copy_protection, require_copy_safe_draft
report = analyze_copy_protection("후보 원고", ["참고 소설 본문 1", "참고 소설 본문 2"])
# 자동 재사용 시에는 강제 게이트 사용 (review/blocked/검사 불가이면 예외)
require_copy_safe_draft("후보 원고", ["참고 소설 본문 1"])
```

`ParsedReference` 입력도 지원한다. 단, 기존 SQLite Reference Profile은 통계/숫자만 저장하므로 **원문 비교용으로 직접 사용할 수 없다.** 사용자는 검사 시마다 합법적으로 보유한 참고 파일을 다시 지정해야 한다. **원문을 DB로 가져와 보관하는 방식을 추가하지 않는다.**

### 검증 및 한계

- 신규 테스트: 긴 구간 96자 이상 차단, 48자 검토, 짧은 작품 전체 복제 검토, 공백/구두점/대소문자/NFKC 차이, 다중 원문, 부적합 입력, 경계 크기, 임시 인메모리 해시 충돌 검증, 로컬 CLI 및 데이터 미저장, 네트워크 차단.
- `clear`는 **단어 교체·부분 번역·요약·유사 플롯/설정·문체 모사·복선 구조 도용**을 탐지하지 못한다. 반대로 흔한 관용 문구의 48자 이상 일치가 거짓 양성일 수 있다. 사람이 검토할 필요가 있다.
- **외부의 모든 저작물**을 확인하지 않으며, **입력한 원문만 검사한다**. 원문 없이 DB 통계만 있으면 검사를 통과시킬 수 없고 검사를 실패로 처리한다.
- Novel Bible, 로컬 AI Writer, 자동 재집필·유사성 확장, 출판 승인 통제는 후속 단계 작업. 현 단계에서 실제 AI 원고를 생성하거나 출판하지 않는다.
- GitHub, 원격 서버, 외부 AI, 데이터베이스 변경 없음. `.github`/`.git` 파일은 누적 ZIP에서 제외.

다음 39단계는 **유사성 검사 기준선**: 부분 중복률, 문단 단위 반복, 편집거리/의미적 유사성의 역할과 한계를 추가한다.
